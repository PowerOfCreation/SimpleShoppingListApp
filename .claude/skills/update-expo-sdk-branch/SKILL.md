---
name: update-expo-sdk-branch
description: Use when checking out and updating a Renovate branch that bumps Expo/React Native packages in frontend/ (e.g. renovate/expo-sdk), to rebase it onto main and align versions with what the installed Expo SDK actually expects, verified via offline expo-doctor.
---

Renovate bumps each `frontend/` package to its own latest version independently. For Expo/React Native, that's wrong: `expo`, `react-native`, `react`, `react-native-reanimated`, `react-native-worklets`, `react-native-gesture-handler`, `react-native-safe-area-context`, and `expo-dev-client` must match the exact (or SDK-pinned range) versions the installed Expo SDK declares as compatible, not just "whatever is newest on npm". Drifting past that breaks builds later, often silently.

## Procedure

1. **Checkout + rebase**
   ```bash
   git fetch origin
   git checkout -b <branch> origin/<branch>   # e.g. renovate/expo-sdk
   git rebase main
   ```
   Resolve conflicts normally if any (package.json/pnpm-lock.yaml fields main has since changed, e.g. `packageManager` pin, unrelated dep bumps).

2. **Install with the pinned pnpm, no new build-script approvals**
   ```bash
   cd frontend
   corepack pnpm install --frozen-lockfile
   ```
   `corepack pnpm` resolves the exact version from `package.json`'s `packageManager` field — don't use a bare global `pnpm`, versions can mismatch and corrupt the pnpm store format. Do **not** run `pnpm approve-builds` — if the install prompts for new build-script permissions, that's a signal to stop and ask, not to grant blindly.

3. **Check against the SDK, offline** (mirrors what CI runs — see `frontend/.github` workflow / AGENTS.md)
   ```bash
   EXPO_OFFLINE=1 corepack pnpm exec expo-doctor
   ```
   Look specifically for "Check that packages match versions required by installed Expo SDK". If it fails, note every package + expected version it lists.

4. **Align to SDK-expected versions — do not use `expo install --fix` directly**
   `EXPO_OFFLINE=1 expo install --fix` internally shells out to a bare `pnpm` from PATH, which in offline mode can resolve to a different pnpm major version than the one that built `node_modules`, throwing `ERR_PNPM_UNEXPECTED_STORE`. Instead, take the exact `pnpm add ...` command it would have run (visible in its output, or reconstruct from the `expo-doctor`/`expo install --check` "expected version" table) and run it yourself through the pinned pnpm:
   ```bash
   EXPO_OFFLINE=1 corepack pnpm add <pkg>@<expected-version> <pkg2>@<expected-version> ...
   ```

5. **Check for peer-dep fallout from the downgrade**
   ```bash
   corepack pnpm peers check
   ```
   Compare against a `peers check` on plain `main` first, to separate pre-existing warnings (ignore) from ones your change introduced. A common one: `react-test-renderer` (devDependency) needs to stay in lockstep with the `react` version — if you pinned `react` back down, downgrade `react-test-renderer` to match too.

6. **Re-verify**
   ```bash
   EXPO_OFFLINE=1 corepack pnpm exec expo-doctor   # expect 21/21 (or however many) checks passed
   rm -rf .expo                                     # drop cache generated by the CLI runs above
   EXPO_OFFLINE=1 corepack pnpm lint
   EXPO_OFFLINE=1 corepack pnpm test
   ```
   Note: running `expo`/`expo-doctor` locally generates a gitignored `.expo/static-tmp/` cache that eslint will pick up and fail on if not cleared first — that failure is cache clutter, not a real regression; delete `.expo` and re-lint to confirm.

7. **Don't chase everything `pnpm outdated` lists.** Only the Expo/RN-family packages `expo-doctor` flags are in scope for this branch. A concurrent SDK major bump (e.g. `renovate/major-expo-sdk`) and unrelated dev-tooling minors are separate, out of scope — updating them here is exactly the "blind update" this workflow exists to avoid.

8. **Commit + push**
   Only `frontend/package.json` and `frontend/pnpm-lock.yaml` should be touched by step 4-5. See [[feedback_no_coauthor_trailer]] — no `Co-Authored-By` trailer. Since the branch was rebased, pushing needs `git push --force-with-lease origin <branch>`.
