## Project Overview

Go REST API backend for a shopping list app. Uses Echo (HTTP), PostgreSQL (via pgx/v5), and sqlc for type-safe query generation. The frontend is a React Native/Expo app located at `../frontend/`.

## Commands

```bash
# Start only the database
docker compose up -d postgres

go run ./cmd/api

# Hot reload (requires `air` installed)
air

# Run all tests (uses testcontainers — Docker must be running)
go test ./...

# Run a single test
go test ./internal/infrastructure/db/postgres/... -run TestNewConnection

# Regenerate sqlc code after modifying sql/queries/*.sql or migrations/
sqlc generate

# Run full stack via Docker
docker compose up
```

## Architecture

The codebase follows Clean Architecture with strict layer separation:

```
cmd/api/                          → Entry point; wires all dependencies
internal/
  domain/
    entities/                     → Core types (ToDoList, ToDo, ValidatedToDoList)
    repositories/                 → Repository interfaces (no implementations here)
    events/                       → Domain event definitions
  application/
    interfaces/                   → Service + EventHandler interfaces
    services/                     → Business logic (ToDoListService, EventDispatcher)
    command/                      → Command + result types (write operations)
    query/                        → Query result types (read operations)
    mapper/                       → Maps entities → application results
    common/                       → Shared result DTOs
  infrastructure/db/
    sqlc/                         → Auto-generated by sqlc (do not edit manually)
    postgres/                     → sqlc repo implementations + DB connection
  interface/api/rest/
    dto/request/                  → Incoming request structs
    dto/response/                 → Outgoing response structs
    dto/mapper/                   → Maps application results → HTTP responses
    todo-list-controller.go       → HTTP handlers
    event-controller.go           → Event sync endpoint
  testhelpers/                    → Shared test setup (testcontainers)
migrations/                       → SQL migration files (source of truth for schema)
sql/queries/                      → Raw SQL queries consumed by sqlc
```

## Key Patterns

**Validated types**: Domain entities are not persisted directly. `NewValidatedToDoList()` wraps a `ToDoList` after passing validation; repository methods only accept the validated type. This makes invalid state unrepresentable at compile time.

**Commands/Queries**: Service methods take command/query structs as input and return typed result structs. This mirrors CQRS without a full bus.

**Soft deletes**: Both `todo_lists` and `todos` have a `deleted_at` column. All queries filter `WHERE deleted_at IS NULL`.

**Event syncing**: The frontend syncs offline mutations via `POST /api/v1/events`. `EventDispatcher` routes events by `event_type` string to registered `EventHandler` implementations. Unknown event types are silently ignored for forward compatibility.

**sqlc workflow**: Edit `sql/queries/*.sql`, run `sqlc generate`, then implement changes in `internal/infrastructure/db/postgres/`. Never edit files under `internal/infrastructure/db/sqlc/` manually.

## Testing

Tests use [testcontainers-go](https://testcontainers.com/) to spin up a real Postgres instance — no mocking of the database layer. Call `testhelpers.SetupTestDB(t)` to get a container with the schema applied, and `defer testDB.Close(t)` to clean up.

Docker must be running when executing tests.
